# 城市轨道交通规划沙盘

## 现状与规划

每个内置城市以原始线网快照作为规划基础。读取快照时，线路标记为 `existing`、`locked: true`、`visible: true`。自建、复制和支线默认为 `planned`。用户可解锁现状线路，在当前浏览器副本内编辑；`public/transit/` 中的快照不会被编辑操作改写，可用“恢复内置原始线路”找回。

`construction` 是用户标记的在建线路，不表示数据源已经提供在建工程。地图用实线表示现状线、虚线表示在建线、加粗表示规划线；颜色仍可按线路自定义。`visible: false` 只过滤地图几何与图例，不删除数据，也不改变统计。

解锁是显式操作。锁定的线路不能删除、改拓扑或调整顺序；属于任何锁定线路的站点和控制点不能移动或删除。复制现状线路会产生新 ID、`planned` 状态和 `sourceLineId`，站点仍引用现状站点，控制点则复制为独立对象。因此规划副本可以调整走向；若要改变共享现状站点的位置，先从规划线路移除引用，再创建新站。

“从首端/末端延长”对现状线路先创建规划副本；从站点新建支线则以所选站作为首节点。规划操作不会自动移除现状线路。城市内重置会清除规划层，保留当前方案的现状线网。

支线使用 `parentLineId` 归到当前主线路下面，各支段保留独立节点顺序以表达分叉。列表嵌套显示，地图线路名、颜色及站点所属线路按主线路计算，同一线路的主线和支线不被重复计为换乘；城市线路数也只计主线路。主线路统计包含所属支段，线路长度按几何线段去重累计。删除主线路同时删除所属支段，删除一段支线保留主线，均可撤销。旧版创建的独立支线可以用“支线归属”明确选择主线路；不会猜测归属自动改变用户数据。

开始添加站点、控制点或多选时，自动退出展示模式。`Ctrl+S` / `Cmd+S` 明确保存当前方案到浏览器存储，在输入框内也会先提交编辑内容；保存失败提示导出备份。JSON 文件备份仍使用“导出 JSON”。

## 方案保存

每个城市单独使用 `metro-planner.scenarios.<cityId>`，自主规划使用 `metro-planner.scenarios.custom`。方案保存完整 schema v2 项目，最多 5 个。默认单方案继续沿用原有城市项目键，避免保存重复快照。新建方案从当前内置城市快照开始；复制方案保留当前规划。切换先保存当前方案，再载入目标方案并清空撤销历史和临时编辑状态，地图视角不变。

浏览器存储空间有限。若方案保存失败，当前内存项目继续可导出 JSON；出现提示时应立即导出备份。方案快照与内置数据分开保存；数据源更新不会自动覆盖已有方案。旧城市项目中 `amap-` 前缀线路在导入时识别为现状并默认锁定；普通旧项目线路默认为规划。

## 距离和数量

每条线路的长度沿有序站点和控制点逐段用 Haversine 计算；环线加上末节点至首节点闭合段。站距在相邻站点之间沿控制点累计。城市规划新增里程排除与现状完全同坐标的线段；这是几何比较，线路移动后会按新形状重新计入。大规模施工或运营数据仍以运营方公告为准。
