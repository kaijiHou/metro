# Metro Planner · 地铁线路规划器

一个在真实地图上规划地铁线路的轻量编辑器。用站点和控制点组成有序线路，拖动节点调整形状，并将项目保存在浏览器或导出为 JSON。

## 功能

- 地图右上角“展示模式”隐藏站点圆圈和控制点，保留站名，显示沿线名称与颜色图例；“返回编辑”恢复标记。
- Phase 3 规划沙盘：现状线路默认锁定；可解锁副本、显隐线路、区分已建成/在建/规划、查看线路与城市统计。
- 可将现状线路复制为规划线、从首端或末端延长、从已有站点新建支线；每个城市可保存最多 5 个独立方案。
- 支线归属于当前主线路，沿用其颜色和地图线路标注；旧独立支线可通过“支线归属”归入主线路。按 `Ctrl+S` 明确保存当前方案并显示结果，也继续自动保存。
- 多条线路：创建、命名、改色、选中和删除。
- 城市导航：直接选择常用城市，或搜索 OpenStreetMap 收录的世界各地城市；刷新后恢复上次地图位置。内置城市会载入现状线网，各城市分别保存方案。
- 地图添加、选择、命名、拖动及删除站点；线路按节点顺序连接。
- 站点面板“多选删除”支持地图点选、列表勾选与全选；批量删除可一次撤销。
- 点击线路插入控制点，拖动调整走向；可连续插入多个点，节点也可上移、下移或从当前线路移除。
- 节点列表旁可继续新增站点或从最前面头插；已有站点支持按站名、线路编号搜索，显示所属线路，并可加入首端或末端。
- 顶部“撤销 / 重做”支持纠正编辑，键盘快捷键为 `Ctrl+Z` / `Ctrl+Y`（Mac 为 `⌘Z` / `⌘⇧Z`）。
- 已有站点可加入其他线路；同一站点被多条线路引用时显示为换乘站。
- 浏览、添加站点与添加控制点模式分离；地图支持平移、滚轮缩放与缩放按钮。
- 自动保存到 localStorage；导出版本 2 JSON，旧版本 1 JSON 可导入并自动升级。

## 站到站路线与有轨电车

左侧 **站到站 · 路线查询**：选择城市，输入并从结果选中起点、终点，点击 **规划路线**。默认按预计用时推荐，也可选择换乘最少或乘坐站数最少。地图高亮线路及起终点；结果列出乘坐线路、方向、换乘站和沿途站点。点击地图站点后的详情或站点编辑面板，也可直接“设为起点／终点”。

默认使用现状快照，查询不会替换正在编辑的项目。选择“我的当前规划”可查询修改后的网络，勾选“包含在建／规划区间”用于沙盘模拟；未开通路线会明确提示。相同名字不会自动视为换乘，实际连接以共用站点ID为准。

新增武汉车都T1、光谷L1/L2/L3，南京河西、麒麟电车；北京西郊、佛山南海电车使用原快照。旧规划自动显示只读电车补充，点击“把电车加入当前规划”后可解锁修改，支持撤销，已有站点修改保留。新增电车的站位、核实换乘表、方向差异、许可与覆盖限制见 [补充数据说明](src/data/README.md)。尚非全国电车全覆盖。

**时间是估算，不是实时导航**：采用站间连线距离，地铁40／电车22公里每小时，每区间加30秒停站；候车约2.5／4分钟，换乘另加5分钟。不检查首末班车、实时班次或临时停运；出行前以运营公告为准。

## 技术栈与地图

Vite、React 18、TypeScript（严格检查）、MapLibre GL JS、Zustand、GeoJSON、localStorage。底图使用 [OpenFreeMap](https://openfreemap.org/) 的公开 Liberty 样式，地图数据来自 OpenStreetMap。底图需要联网。

## 安装与运行

需要 Node.js 24 或更新版本和 npm；本机共享资料使用 Node 内置 SQLite。启动脚本优先使用兼容版本，可自动使用这台电脑已有的 Codex Node 24。

Windows 本机已安装依赖后，双击 `scripts/start-metro.cmd` 即可启动并自动打开浏览器。地址固定为 `http://127.0.0.1:5173/`；使用期间保留启动窗口，关闭窗口即可停止服务。已在运行时会直接打开页面。

手动安装与启动：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。构建、检查与测试：

```sh
npm run lint
npm run build
npm test
```

GitHub Actions 会在每次 push 和 pull request 时使用 Node.js 24 执行 `npm ci`、lint、全部单元测试和生产构建。

内置 58 个城市线网、397 条线路或支段的高德地铁图快照（获取于 2026-10-07），支持修改站点和线路。数据来源与更新方式见 [真实线网说明](docs/TRANSIT_DATA.md)。

## 浏览器回归验证

浏览器流程使用 Python Playwright，依赖锁定在 `validation/requirements.txt`。在 Windows PowerShell 中准备一次环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r validation\requirements.txt
python -m playwright install chromium
```

如果机器已经安装 Chrome，可跳过最后一条浏览器下载命令，并在运行脚本前设置 `$env:METRO_BROWSER_CHANNEL = 'chrome'`。不设置该变量时，脚本使用 Playwright 安装的 Chromium。

先在一个终端启动生产预览：

```powershell
npm ci
npm run build
npm run preview
```

再在已激活虚拟环境的另一个终端运行：

```powershell
$env:METRO_URL = 'http://127.0.0.1:4173/'
$env:METRO_BROWSER_CHANNEL = 'chrome' # 仅在复用本机 Chrome 时设置
python validation\browser_flow.py
python validation\city_network_flow.py
```

该流程需要访问 OpenFreeMap，因此作为本地回归验证运行，不放入 GitHub CI。脚本覆盖站点与控制点编辑、旧数据迁移，并确认线路改名、改色后原 Marker DOM 节点保持不变。

## 使用

1. 左侧“城市与真实线路”可选择城市线网、快捷按钮或搜索。武汉等内置城市首次载入真实线路，后续恢复你的修改；“自主规划”保留自建项目。现状线路默认锁定，可复制为规划线路或明确解锁副本。“恢复内置原始线路”可还原当前城市，支持撤销。
2. “规划方案”可从现状新建方案、复制当前方案、重命名、切换或删除；方案按城市分开自动保存。切换方案会清空撤销历史，保留地图视角。
3. 点击“新建线路”，可修改名称、颜色、状态与显示方式；线路面板提供复制、首尾延长和全显/全隐。规划统计显示线路长度和站距。
4. 当前线路下方的“添加站点”区域先选择开头或末尾，再点“去地图放新站”：点击地图空白处新建站，点击已有站点直接接入当前线路；添加结束点“完成添加”。顶部“添加站点”入口也支持地图点站接入。
5. 点击“添加控制点”，再直接点击线路上的一段，控制点会插入正确位置。可以接着点击线路加入第二个；拖动地图上的小菱形改变走向，完成后点“浏览 / 选择”。若想先指定两节点之间的位置，也可使用列表中的“插入控制点”，再点击地图放置。
6. 在“节点顺序”中点击站点名称，下面会出现改名输入框。点 ↑、↓ 调整顺序，用 × 从当前线路移除。移除站点节点会保留站点；控制点失去最后一条线路引用时会自动删除。操作失误可点顶部“撤销”，或按 `Ctrl+Z`；`Ctrl+C` 是复制。
7. “使用已有站点”支持搜索站名或线路编号；结果直接显示站名和所属线路，点击结果就加入选定的开头或末尾。当前线路已有站显示“已在线路中”，不会重复加入。控制点不算站，也不参与换乘。
8. 项目更改自动保存。使用顶部“导出 JSON”备份，或“导入 JSON”恢复。旧版 v1 文件会升级为 v2。城市内“重置项目”会清空规划线路并保留现状线网；顶部“新建项目”可指定新名称，选择“保存并新建”下载当前项目备份，或“不保存，直接新建”开始空项目。

## 目录

- `src/components/`：地图与编辑面板。
- `src/store/`：Zustand 单一项目状态与编辑操作。
- `src/models/`：数据类型。
- `src/utils/`：GeoJSON、校验、持久化。
- `src/config/`：底图配置。
- `docs/`：研究、架构、数据格式与测试记录。

## 当前限制与后续计划

线路按相邻节点之间的直线段绘制，不代表隧道或轨道的测绘路径。撤销历史最多保留最近 50 次项目修改，刷新页面后会清空；GeoJSON/KML 文件导出和截图尚未实现。项目保存在当前浏览器，不跨设备同步；清理浏览器数据会清除本地副本，请导出 JSON 备份。旧版浏览器数据会从 `metro-planner.project.v1` 自动迁移到稳定键 `metro-planner.project`；迁移失败会提示并保留旧数据。世界城市搜索需要联网，结果范围取决于 OpenStreetMap 的收录情况。

详细设计见 [规划模型](docs/PLANNING_MODEL.md)、[架构说明](docs/ARCHITECTURE.md)、[数据格式](docs/DATA_FORMAT.md) 和 [真实线网说明](docs/TRANSIT_DATA.md)。

## Phase 4 第一批：全国漫游与站点出口

1. 在武汉保留自己的规划，点击顶部 **浏览模式**。保持“全国线网自动展示”开启，直接拖地图到长沙；视野覆盖两城时两城均显示。全国尺度显示城市点，放大后显示线路、站点和站名。
2. 点击站点或站名，右侧显示城市、线路与出入口资料。OSM 按需查询，第三方数据可能缺失；没有可信关联时显示“暂无可靠出口数据”，不表示车站没有出口。无去向字段时显示“出口方向暂未收录”。失败可重新查询。
3. 点击出口可定位其坐标。出口位置不等于步行导航；本期不提供步行时间、GPS 或路线规划。
4. “仅看已建成线路”读取内置现状快照；取消后当前城市显示自己的规划副本，其余城市仍是只读快照。快照不保证反映今日运营状态。
5. “返回我的规划城市”只移动地图；切回 **规划模式** 后继续原方案，漫游不会替换项目、切换 Scenario 或增加撤销记录。浏览中城市下拉只定位，不切换编辑项目。

Phase 4B 已实现下方的旅行足迹、相册与 ZIP 备份。GPS 仍仅有 [下一阶段设计](docs/NAVIGATION_ROADMAP.md)。地铁规划继续使用原 localStorage 与 JSON 导出。

全国漫游复用原有 58 个城市快照；数据日期、第三方授权局限见 [线网数据](docs/TRANSIT_DATA.md)。出口为 © OpenStreetMap contributors，ODbL；关联规则、缓存和人工导入见 [站点出口](docs/STATION_EXITS.md)。浏览器验收命令：`.venv\Scripts\python.exe validation/phase4_roaming_flow.py`，使用独立浏览器空间，不读取个人浏览数据；出口场景采用明确的模拟响应，真实服务可用性另行记录。

## 我的旅行足迹（Phase 4B）

**市级地图与县级市统一显示**：武汉等原有城市始终保留，汉川、洪湖等县级市可以独立点亮，普通县和区隐藏。点亮洪湖会同时点亮整个荆州；省份清单自动汇总。点亮市级地区不会反向点亮所有下辖县级市。原有日期、备注、照片和备份继续有效。

当前收录352个已核对县级市，采用2017历史几何，尚非现行全国全覆盖；来源与调研见 [县级市足迹升级说明](docs/FOOTPRINT_COUNTY_UPGRADE.md)。

鼠标悬停市级区域可显示城市名和省份。足迹轮廓、目录和默认图随项目保存在本机，地名使用系统字体；断网后保持本地服务运行即可使用，不用额外下载离线包。轨道交通页的详细道路底图目前仍在线加载。

点击顶部“我的旅行足迹”：深色全国轮廓总览，点击城市只高亮并打开详情，**不会自动放大成满屏市界**。左侧按省筛选时定位该省；可自己缩放。市界真实点亮，省份只作轮廓、分类和汇总；不是街道导航地图。返回“轨道交通地图”继续原项目与方案。

1. 搜索“武汉市”，点击城市后选择“标记已到过”。日期可不填，也能添加多次到访日期和备注；点亮武汉不会点亮黄冈、襄阳或整省。
2. 相册点击“上传照片”可多选 JPEG/PNG/WebP。全部照片=默认+个人；城市默认=系统获授权图片；我的照片=个人上传。左右按钮、键盘方向键、缩略图与手机滑动都可切图，点图放大。
3. 个人照片可设置封面、排序、填写说明/日期或确认删除；删封面会回退到其它个人图或系统默认。取消点亮不会删相册、备注和到访日期。
4. “导出我的全部旅行足迹 ZIP”会包含记录和个人原图。导入可选合并或覆盖，**只操作旅行库**；覆盖前强提示。无效路径、未知城市、损坏图片、错误归属/版本和超限压缩包会拒绝，失败不留下半套恢复。

当前支持 **339 个市级区域，33 个省级分组**，基于 OCHA/HDX COD-AB 的2020资源版本，非现行法定界线图。34个省级轮廓用于展示，台湾整省几何不当作一个城市；21个不符层级的来源单元未纳入（不等于只缺21个城市）。莱芜合并到济南，其他历史行政调整可能未完全反映。城市分母按339个市级单元及已收录的省直辖县级市计算，县级市归属父市时对父市去重。完整范围、原始SHP/码表PCODE精确映射与CC BY 3.0 IGO署名见 [数据来源](docs/FOOTPRINT_DATA_SOURCES.md)。

系统实拍默认图目前只有**武汉黄鹤楼**，来自GoodFreePhotos，文件页及使用条款明确Public Domain/CC0；其余城市用明确标注的城市文字占位，不借用其它城市照片。默认图的来源、许可可在相册点开查看。

旅行记录和个人照片统一保存在本机 **`data/travel.sqlite`**，通过本机服务读写；Chrome、Edge和内置浏览器共用同一文件。单张20MB、最多4000万像素（解码后检查），全库300张/160MB；多文件逐项反馈。数据库禁用、损坏或空间不足会显示失败，不能当作保存成功。

**不同浏览器共用本机资料**：点亮立即保存，日期和备注点击保存按钮；打开的页面约2秒同步变化。旧浏览器记录在首次打开足迹时自动合并，原浏览器数据保留。资料不发布到公网，数据库被Git忽略且禁止静态下载。可以导出ZIP，或关闭程序后复制`data/travel.sqlite`备份。仅静态托管的GitHub页面无法直接读写电脑文件，须用本机启动脚本。详见 [旅行足迹使用与恢复](docs/TRAVEL_FOOTPRINT.md)。

共享存储验收：`.venv\Scripts\python.exe validation/phase4b_shared_flow.py`，使用独立测试数据库和Chrome/Edge，自动验证迁移、共享与重启持久化，不读取个人资料。
